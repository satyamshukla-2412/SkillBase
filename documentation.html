SkillBase — Project Documentation & Technical Overview
A Pure Vanilla Web Platform for Peer-to-Peer Skill Matching & Direct Talent Discovery
Live URL: https://skillbase24.vercel.app Repository: github.com/satyamshukla-2412/SkillBase Architecture: HTML5 / CSS3 / Vanilla JS (ES6+)

1. Executive Summary & Core Concept

SkillBase is a web-based skill-exchange and talent matching platform designed to connect people who HAVE valuable skills with individuals and organizations who NEED talent for projects, tasks, and creative collaborations.

The platform eliminates intermediaries, recruitment agencies, and third-party fees by offering a direct, transparent match-making mechanism powered by deterministic keyword matching and geographic proximity scoring.

2. Target Personas & Platform Roles

Target Persona Who They Are Primary Objectives Key Features Used
Skill Provider Freelancers, developers, designers, content writers, skilled students, and domain specialists. Showcase expertise, build a public portfolio, find matching project leads, and receive direct inquiries. Profile manager, dynamic skill tag additions/removals, matches feed, received messages inbox.
Skill Seeker Project owners, startup founders, community organizers, NGOs, and teams needing skilled help. Post concrete project requirements, specify budgets, search qualified talent, and initiate contact. Requirement posting, skill & city search filters, candidate match scoring, direct inquiry modal.

3. Technology Stack & Tools Used

Layer Technology Implementation Details
Markup (Structure) HTML5 (Semantic) Multi-page architecture with 7 distinct semantic views: index.html, login.html, register.html, provider.html, seeker.html, matches.html, and profile.html.
Styling (Aesthetics) Vanilla CSS3 Zero external UI frameworks (No Bootstrap, No Tailwind). Uses native CSS Variables, CSS Grid, Flexbox, responsive media queries, and dual external/embedded fail-safe stylesheets.
Client Logic Vanilla JavaScript (ES6+) Modular separation of concerns across storage.js, auth.js, main.js, matches.js, provider.js, and seeker.js without heavy JS libraries.
Persistence Browser LocalStorage Client-side persistence for user registrations, active authentication sessions, requirements, and sent/received contact messages. Pre-seeded with 8 sample profiles.
Serverless Runtime Node.js (HTTP / Lambda) Universal entrypoint (app.js) that serves all assets from an in-memory routing table with 100% reliability, MIME accuracy, and clean URL resolution.
Hosting & CI/CD GitHub & Vercel Automated deployments triggered directly from GitHub commits on the main branch to Vercel's global edge network.

4. Design Philosophy & Approach

The platform was intentionally crafted to feel like a clean, practical, hand-designed website rather than a generic AI-generated landing page template.

  • Natural Aesthetics: Uses a crisp light background (#f9fafb), dark charcoal text (#1f2a37), and a professional collegiate blue primary color (#1a56db).
  • Modest Visual Weight: Modest border-radii (4px to 6px), standard 1px solid borders, and clear typographic hierarchy without glowing neon gradients, glassmorphism, or 3D blobs.
  • Zero Third-Party Assets: Avoids external font scripts or icon packs that could break offline or behind restrictive networks.

6. How the Platform Works (User Flows)

1. Homepage Discovery

Visitors are greeted by the clean hero section ("Connect Skills. Find Opportunities.") with two clear pathways: "I Have Skills" (leading to Provider registration) and "I Need Skills" (leading to Seeker registration). Below the hero, three value propositions are highlighted: Verified Skills, Smart Matching, and Direct Contact.

2. Dynamic Registration & Authentication

On register.html, selecting Skill Provider dynamically opens inputs for primary skills, experience duration, location, and bio. Selecting Skill Seeker dynamically switches to required skill, project deliverables, location, and budget. Submitting validates input, ensures no duplicate emails, saves the user to LocalStorage, logs in automatically, and redirects to their dashboard.

3. Provider Dashboard Workflow

Providers can inspect their public card, add new skills on the fly (which immediately generates a removable badge), edit their bio and experience level via a clean modal, and view project inquiries sent to them by seekers.

4. Seeker Dashboard Workflow

Seekers view their active requirement (deliverable description, budget, and target city), edit requirement parameters at any time, perform direct candidate searches, and review the history of inquiries they have initiated.

7. Deterministic Skill-Matching Algorithm

SkillBase uses a transparent, deterministic matching algorithm coded in vanilla JavaScript (js/storage.js and js/matches.js):

Matching Stage Condition Score Awarded Resulting Badge & Priority
Skill Keyword Match Seeker requirement matches any Provider skill keyword (e.g., "Web Development"). +10 points Skill Match
Location Bonus Candidate location matches Seeker location (e.g., both in "Mumbai"). +5 points Location Match
Combined Top Match Both skill keyword and location criteria match simultaneously. +15 points Top Match (Skill + Location) (Ranked 1st)
General Browse No specific search query entered (browsing directory). +5 points (base) Displays all available candidates sorted alphabetically.
Dual-Mode Discovery: On matches.html, users can toggle between "Find Skill Providers" (talent directory) and "Find Project Requirements" (open project opportunities).

8. Data Storage Architecture (LocalStorage Schema)

The platform runs completely client-side using three normalized LocalStorage tables:

1. 'skillbase_users'     -> Array of user objects (Providers & Seekers)
   Structure: { id, name, email, password, role, skills, experience, location, description, requiredSkill, budget }

2. 'skillbase_current_user' -> Object representing the currently logged-in session user

3. 'skillbase_messages'  -> Array of inquiry messages
   Structure: { id, senderName, senderEmail, recipientId, recipientName, recipientRole, message, date }
